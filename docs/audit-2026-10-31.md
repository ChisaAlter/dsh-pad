## 修复前结论与优先级

确认 **15 项可行动问题：P1 两项、P2 十一项、P3 两项**。其中深层 JSON 能使隔离 Host 进程退出；分栏手势与新增面板竞争能直接造成卡片从当前界面消失。它们与最初症状相关，但没有用户原窗口的同期日志，不能据此认定每次消失都由同一原因引起。

- P1：应优先修复的进程可用性或凭据边界问题。
- P2：明确可复现的功能、状态一致性、资源管理或更新可靠性问题。
- P3：受限场景中的诊断或版本比较缺陷。

建议顺序：先处理 01–02 的数据与凭据边界，再处理 03–06 的隐藏/布局/订阅和启动回滚，随后处理 07–11 的状态与资源问题，最后处理 12–15 的运行时、更新和诊断。本节保留审查时的修复建议，实施状态以修复表为准。

## 01 · P1 · 小型深层 JSON 可使 Host 退出

**位置：**[sources.ts:23](../src/host/sources.ts#L23)、[routes.ts:146](../src/host/routes.ts#L146)、[hub.ts:228](../src/host/hub.ts#L228)、[hub.ts:327](../src/host/hub.ts#L327)。

**触发：**一个存在 SSE 订阅的 JSON 数据源返回 10,000 层数组，只需要 20,001 字节，远低于 512 KiB 限制。JSON.parse 成功，读数被接受为 ok；随后推送时 JSON.stringify 抛出 RangeError。异常没有在订阅 fan-out 和 fire-and-forget tick 处隔离。

**证据及影响：**真实 PanelStore、ReadingCache、DataHub 和路由的独立复现捕获到未处理拒绝；不安装全局捕获器的独立 Node 进程退出码为 1。坏值留在 hub，panels API 同样抛错。实测未攻击正在运行的桌面 Host；若实际宿主另有全局异常处理，退出行为取决于该处理，但 API 和轮询故障仍存在。

**修复方向：**接纳 JSON 前迭代限制结构深度/节点规模；广播逐订阅者隔离异常；所有定时异步入口处理拒绝并可靠重排。只包住 SSE stringify 不足以修复已进入 hub 的坏值。

## 02 · P1 · 跨主机重定向转发自定义密钥头和含凭据请求体

**位置：**[sources.ts:196](../src/host/sources.ts#L196)、[sources.ts:206](../src/host/sources.ts#L206)。

**触发：**HTTP 源填入 `{{env:NAME}}`，使用 x-api-key 等自定义头，或在 POST body 中传凭据；最初 URL 返回跨 origin 重定向。当前直接使用 redirect: follow。

**证据及影响：**本地源从 127.0.0.1 重定向到 localhost，hostname 与端口均不同。GET 302 中原生 fetch 移除了 Authorization，却把合成 x-api-key 发给目标；POST 307 还重发含合成 token 的 JSON body。两次 reading 都返回成功。响应脱敏无法收回已经发送给其他主机的凭据。触发需要源返回跨主机重定向，不是所有 HTTP 请求都会泄露。

**修复方向：**手动、有界处理每一跳；含凭据请求默认只允许同 origin 跳转。跨 origin 拒绝或按明确允许列表重建请求，覆盖自定义头与请求体，不能只依赖 fetch 对 Authorization 的特殊保护。

## 03 · P2 · 分栏结束提交旧树，使并发新增的卡片消失

**位置：**[Dock.tsx:525](../src/client/Dock.tsx#L525)、[Dock.tsx:555](../src/client/Dock.tsx#L555)、[Dock.tsx:197](../src/client/Dock.tsx#L197)。

**触发：**按住已有分栏线，期间其他会话或工具创建面板并通过 SSE 加入列表，再松手；不需要实际移动鼠标。

**证据及影响：**真实 React DOM 松手前是 a/b/c 三张卡，松手后只剩 a/b，但 snapshot 始终含 a/b/c。手势捕获的旧 final 被直接提交；正规化 snapshot 的 treeSignature 已相同，同步 effect 不再补回新卡片。持续数据 tick 不会恢复，重开坞或后续布局变化才能恢复。服务端记录未删除，这是本轮直接复现的“卡片消失”。

**修复方向：**提交时读取最新 panels，对 final 按最新 ids 正规化，并使本地显示树与持久树使用同一个结果；同类卡片拖动提交也应重新读取最新集合。

## 04 · P2 · Dock 卸载后活动拖动仍可写入旧布局

**位置：**[Dock.tsx:228](../src/client/Dock.tsx#L228)、[Dock.tsx:668](../src/client/Dock.tsx#L668)。

**触发：**拖动期间 Dock 因 slot 重建、插件卸载/重载或渲染边界恢复而卸载，随后指针继续移动/释放。

**证据及影响：**真实 React unmount 后 document 的 pointermove/up/cancel 监听仍各有一个；后续事件仍把持久位置从 (100,100) 改为 (250,200)。旧闭包可覆盖恢复后实例的布局。卸载 effect 只清 timer，没有活动手势的统一清理所有权；分栏、卡片和其他 drag/resize 路径也有同类模式。

**修复方向：**统一持有活动 gesture 的 disposer 或 AbortController，卸载/隐藏/新手势开始时取消；取消只清理、不提交，清理幂等。

## 05 · P2 · 折叠卡片放大后没有加入数据源订阅

**位置：**[PanelCard.tsx:276](../src/client/PanelCard.tsx#L276)、[Dock.tsx:1153](../src/client/Dock.tsx#L1153)、[pad-client.ts:462](../src/client/pad-client.ts#L462)。

**触发：**折叠状态的卡片直接点击放大；没有其他客户端订阅该面板。

**证据及影响：**真实 React 中放大视图已显示，但 EventSource watch 仍为空。无首读时持续等待；已有缓存时显示旧值且不再轮询。focusedId 仅保存在 Dock 局部，watchIds 只看 expanded 和 !collapsed。

**修复方向：**将焦点可见面板并入 watch 集合，focus/blur 时登记释放；保留页面隐藏暂停机制。

## 06 · P2 · 吞掉启动异常却不回滚，插件保留半初始化资源

**位置：**[index.ts:86](../src/index.ts#L86)、[index.ts:135](../src/index.ts#L135)、[index.ts:174](../src/index.ts#L174)。

**触发：**调度器和路由已经建立，后续工具注册等步骤失败。apply 捕获并只打印“已禁用”，随后正常返回。

**证据及影响：**真实 Cordis 隔离测试在第三次工具注册注入异常：插件仍 ACTIVE，六个路由、两个工具仍存活。显式 unload 才清理。因 activation 被视为成功，框架无法按启动失败回滚，也不会自动重试完整初始化。该项是异常路径验证，不声称用户当前每次加载都发生第三个工具注册故障。

**修复方向：**在受控子 scope/事务中注册资源，失败显式 dispose 后降级；或让框架感知失败以执行既有回滚。保留“插件故障不拖垮整个 Host”的目标，同时确保资源和状态一致。

## 07 · P2 · 写盘失败仍改变内存，后来无关操作会把失败变更落盘

**位置：**[store.ts:219](../src/host/store.ts#L219)。

**触发：**create/update/remove/模型或状态写入遭遇路径、权限、磁盘等失败。commit 在真正写入前就赋值 this.panels。

**证据及影响：**父路径为普通文件导致 create 以 EEXIST 拒绝，但 list 已含失败记录，通知数仍为 0。恢复路径后只创建另一张卡，磁盘却出现两张。调用方、监听器、内存和磁盘对同一失败操作的认知不一致。

**修复方向：**将基于最新已提交状态的 mutation、写入、内存发布和通知放进同一事务队列；rename 成功后才发布。不要仅在 catch 恢复旧数组，避免覆盖后续排队更新。

## 08 · P2 · AI 刷新的创建和清理不受超时控制，可堵住全部队列

**位置：**[agent-refresh.ts:241](../src/host/agent-refresh.ts#L241)、[agent-refresh.ts:265](../src/host/agent-refresh.ts#L265)、[agent-refresh.ts:282](../src/host/agent-refresh.ts#L282)。

**触发：**preset.resolve/agents.create/setup 挂起，或运行超时后 dispose 等待不退出的工具循环。deadline 到 create 完成后才开始，dispose 又被无期限 await。

**证据及影响：**配置 25ms 超时、观测 90ms，创建仍 running，未传创建 signal，stop 无句柄可 cancel，第二面板未启动。另一用例已触发 cancel，但 dispose 被阻塞后仍占并发且状态 running。默认并发 1 时所有 AI 面板停止刷新。使用受控 Promise 验证边界，没有声称真实 provider 一定会挂起。

**修复方向：**从入口建立统一 deadline/AbortController 并覆盖初始化；传递 create signal；取消立即持久化结果；有界管理清理，同时追踪未退出资源，防止简单释放并发导致后台残留任务无限增加。

## 09 · P2 · pad_update 异步校验后覆盖并发完成的新配置

**位置：**[tools.ts:301](../src/host/tools.ts#L301)、[tools.ts:313](../src/host/tools.ts#L313)、[tools.ts:321](../src/host/tools.ts#L321)。

**触发：**只修改 title 的 pad_update 读取旧 definition 后等待 assertModel；期间用户菜单 setModel(new) 成功，随后校验返回并写入整份旧 definition。

**证据及影响：**隔离断言确认模型先变为 new，再被只改标题的请求改回 old。其他并发字段同样可能被旧快照覆盖。setModel 不递增 version，单比较 version 也不足以防护此竞争。

**修复方向：**异步校验后在事务中将请求字段合并到最新 record；或对 definition/model revision 使用 CAS，冲突时重读重试。

## 10 · P2 · 刷新开始的监听空窗遗留假的 running

**位置：**[agent-refresh.ts:139](../src/host/agent-refresh.ts#L139)、[agent-refresh.ts:170](../src/host/agent-refresh.ts#L170)、[agent-refresh.ts:242](../src/host/agent-refresh.ts#L242)。

**触发：**request 后首次 setAgentRun 的写盘 await 尚未返回，setModel 成功完成。onChange 监听还未建立；旧 run 后来发现过期直接 return，跳过收尾状态更新。

**证据及影响：**未 monkeypatch 的真实 store/scheduler，仅顺序调用 request 和 await setModel：没有创建 agent，isBusy=false，但持久化状态仍 running，nextRunAt 仍是约 60 分钟后。页面会长时间显示刷新中；手动刷新、到期或重启后才纠正。

**修复方向：**第一次 await 前安装运行身份与变更监听，安装后立即核对；所有 early return 统一收尾，按本轮 token 有条件复位，避免覆盖新任务。

## 11 · P2 · SSE 慢消费者没有积压上限

**位置：**[routes.ts:136](../src/host/routes.ts#L136)、[routes.ts:149](../src/host/routes.ts#L149)。

**触发：**连接未关闭、仍 watch 面板，但 Response.body 消费暂停。enqueue 不检查 desiredSize，也没有字节上限或旧数据合并。

**证据及影响：**真实路由与 stub hub，完全不读流时发送 64 个约 512 KiB 事件，之后可读出全部 66 帧共 33,557,298 字节；未读期间 unsubscribe 次数为 0。慢连接可持续占用 Host 内存，恢复后还要重放旧状态。测试有界，没有让真实 Host 耗尽内存。

**修复方向：**每条流使用有界队列，pull 时输出；data 按 panelId 合并最新值；超过限制关闭并释放订阅，让客户端重连取快照，避免阻塞其他连接。

## 12 · P2 · metric 的 tone 可以注入 HTML 属性和 iframe 内脚本

**位置：**[frame-runtime.ts:217](../src/client/frame-runtime.ts#L217)、[frame-runtime.ts:230](../src/client/frame-runtime.ts#L230)。

**触发：**面板将数据中的 tone 原样传给 dsh.ui.metric，再用返回值设置 innerHTML。toneColor 对非预设字符串直接返回，拼接到 style 属性时没有转义。

**证据及影响：**真实 React PanelFrame 中，带引号的 tone 插入带 onerror 的坏 data: 图片，成功触发 refresh bridge stub。外部数据因此成为 iframe 内代码，可使用面板已有 bridge 权限。这是沙箱内注入，未证明 iframe 逃逸或宿主文件系统访问。

**修复方向：**优先只接受语义 tone 枚举；若支持任意色值，验证 CSS 色值并做 HTML 属性转义，或使用 DOM style API。

## 13 · P2 · 更新中断留下混合版本，无启动恢复

**位置：**[update.ts:17](../src/host/update.ts#L17)、[update.ts:238](../src/host/update.ts#L238)、[update.ts:253](../src/host/update.ts#L253)。

**触发：**普通安装副本执行用户发起的更新，在先替换 host、尚未替换 client/manifest 时进程退出、崩溃或断电。源码 checkout 有 .git 保护，不会进入该 apply 路径。

**证据及影响：**仅在假插件目录运行真实更新代码，首个 rename 后终止子进程；结果是 new host、old client、旧 manifest，虽有 backup，新服务没有恢复。它会使下次加载使用混合文件；特定发布是否因此不能启动取决于其兼容性，本轮没有更新真实安装来验证实际发布间的启动失败。

**修复方向：**完整 staging 加持久更新事务，在加载前恢复或完成中断操作；或采用版本目录与原子入口切换。catch 只能处理活进程的异常，不能代替崩溃恢复。

## 14 · P3 · doctor 在空格或中文目录中退出

**位置：**[doctor.mjs:16](../scripts/doctor.mjs#L16)、[doctor.mjs:45](../scripts/doctor.mjs#L45)。

**证据及影响：**原脚本复制到相同结构的假插件：ASCII 路径退出 0；空格和中文路径都退出 1，ENOENT 指向带 %20/%E7... 的文件。pathname 保留 URL 编码，无法当成本地路径使用，导致推荐诊断入口失效；不代表插件在相同目录必然无法加载。

**修复方向：**用 fileURLToPath 转换 URL，替代手工 pathname/盘符处理。

## 15 · P3 · 预发布版本的数字标识符排序错误

**位置：**[update.ts:45](../src/host/update.ts#L45)。

**证据及影响：**compareVersions(rc.10, rc.2) 返回负值，SemVer 应为正。使用预发布 tag 时可能漏报新版本或把旧版本当更新，正常 x.y.z 的数字段比较不受这条影响。
