# 面板设计规范

这份文件是 dsh-pad 面板的设计底线。kit 里的每个类、lint 里的每条规则、`pad_guide`
里的每句话都应该能在这里找到出处。写面板之前先读它，写完用 `npm run panel:check` 收尾。

## 出处

| 参考 | 它实际是什么 | 我们拿它做什么 |
| --- | --- | --- |
| [theinternetdesigns.com](https://theinternetdesigns.com/) | 从 X / Pinterest 收集的真实 UI 截图画廊，不是组件库 | 版式与信息密度的参照：一张卡只讲一件事、列表行用发丝线分隔、数字靠右对齐、留白分组而不是靠边框分组 |
| [Nutlope/hallmark](https://github.com/Nutlope/hallmark) | 「不让页面显得像 AI 生成」的设计方法：Floor / Reflex / Finish 三层门槛，加一个浏览器里的 linter 和一次冷复审 | 我们的硬底线、AI 惯性毛病清单、按宽度渲染的自检，以及 `data-viz.md` 里“仪表盘该有的样子” |
| hallmark `references/data-viz.md` | 表格化的「数据形态 → 图形形态」 | 面板里画什么、不画什么，见下面的「图表」 |

参考不是装饰。README 里写「参考了 X」但代码里找不到对应物，就是没参考。

## 材料（Material）

一个面板只有一套材料，来自 `--pad-*` 令牌，不自带颜色。

| 项 | 值 | 用途 |
| --- | --- | --- |
| 字号 | 10 / 11 / 12 / 13 / 16 / 28 | 10–11 只给元信息（时间、编号、单位）；12–13 是正文；16 是小标题；28 是唯一的主数字 |
| 行高 | 1.2（数字）/ 1.35（正文）/ 1.45（说明） | 数字紧、正文松 |
| 间距 | 4 / 8 / 12 / 16 / 20 | 4px 网格；组件内 4–8，段落间 12，区块间 20 |
| 描边 | 1px `--pad-border` | 只用发丝线，不用阴影分层 |
| 圆角 | 3（chip）/ 6（行）/ 10（卡） | 三层，不混用 |
| 强调色 | `--pad-accent`，一屏一处 | 链接、当前项、图表里唯一的那条序列 |
| 状态色 | `--pad-ok` / `--pad-warn` / `--pad-danger` | 只出现在状态点上，不给整行染色 |

数字一律 `font-variant-numeric: tabular-nums`。

## 图表（来自 data-viz.md）

| 数据是 | 就用 |
| --- | --- |
| 一个值 | 主数字 + 一句话限定语，**不要**只画一条的柱状图 |
| 2–5 个可比较的值 | 一行数字，或横向条 |
| 一段时间序列 | 折线；只当背景用就画 sparkline（无坐标轴、无网格） |
| 超过 7 个分类 | 表格，不是更多颜色 |
| 部分与整体 | 堆叠横条，永远不用饼图/环图/仪表盘 |

- 主数字只能有一个。第二个大数字出现时，要么降级成元信息行，要么删掉。
- 柱：≤24px 粗、2–4px 间隙、零基线、只在数据端 2px 圆角。
- 网格线 1px 实线，3–5 条，不用虚线。
- 文字永远不穿数据色；序列靠色板标识，不靠给文字上色。
- 没有数据就写一句话（“尚未取数”），不编一个 0。

## 门槛（Gate）

### Floor：不过就不发

1. **对比度**：正文与背景的对比度 ≥ 4.5:1；元信息 ≥ 3:1。深色和浅色都要过。
2. **焦点**：每个可点元素都有可见的 `:focus-visible`，键盘能走完。
3. **减弱动效**：有动画/过渡就必须有 `prefers-reduced-motion` 分支。
4. **不许编数据**：拿不到就写“这部分没取到”，不填 0、不画假序列。
5. **窄屏不坏**：280px 宽仍然不横向裁切、不重叠。`npm run panel:check` 跑 280/360/440。

### Reflex：AI 的惯性，看见了就要理由

- 标题上方再挂一行小字（eyebrow）。
- 加字距的大写标签。
- 标题里只有一个词是强调色。
- 一屏 4 个以上等大的数字（KPI 墙）。
- 只有框没有内容的空卡片。
- 每个区块都配一句解释性正文。
- 面板末尾挂一个没人点的“了解更多”。

### Finish：手艺，不阻塞

- 时间、编号、单位用等宽或 tabular。
- 发丝线只画在需要分组的地方，不在每个元素外面套框。
- 空状态、失败状态、只有一条数据的状态都要有具体的句子。

## 自查

```bash
npm run typecheck     # 类型
npx vitest run        # 规则与文档的单测
npm run panel:check   # 把面板定义按 280/360/440 渲染，出图并报告溢出
```

`panel:check` 用真实 `frameDocument` 渲染，和坞里跑的是同一份文档，不是另写一份 mock。
